Путь: `../../Литература/НПО 2026/`

Фактическое содержимое верхнего уровня:

- `UV-Net-main/` — судя по названию, референсная реализация архитектуры UV-Net (не изучалась подробно в рамках этой фиксации).
- `venv/` — отдельное виртуальное окружение этого исследовательского проекта.
- `output/` — выходные артефакты пайплайна.
- `Кронштейн.STEP` (+ папка `Кронштейн/`) — эталонная STEP-модель (алюминиевый кронштейн), используется как валидационная модель в тестах пайплайна согласно его CLAUDE.md.
- Прочее: заметки, .drawio-диаграммы, .docx/.pptx/.pdf черновики статьи — материалы к диссертации/статье, не код.

**Важное расхождение, требующее решения (зафиксировано, не придумано):**
Собственный CLAUDE.md `Литература/НПО 2026/` прямо говорит, что парсер написан на чистом Python с regex **без pythonOCC/OCC**, потому что там используется Python 3.14, несовместимый с OCC-биндингами — и это сознательное решение.
Текущее ТЗ (`Техническое задание.md`, раздел "AI / ML") требует STEP-парсинг именно через `pythonocc-core` (OpenCASCADE) для построения графа граней/рёбер под UV-Net.
→ Это прямое противоречие между существующим исследовательским кодом и требованием ТЗ. Версия Python, доступная для `dev/`, и совместимость `pythonocc-core` с ней — не проверялись в рамках этого шага (см. QUESTIONS.md). Не предполагать заранее, что либо переиспользуем `step_parser.py` как есть, либо ставим OCC — решение зависит от факта, который ещё не проверен.

Формат: SQL-скрипты написаны под PostgreSQL (`SERIAL`, `JSONB`) — по README самой папки, синтаксически проверены (баланс скобок, порядок FK), но **не прогонялись на реальном PostgreSQL-сервере**.
ТЗ требует SQLite как рабочую БД → потребуется адаптация типов (`SERIAL`→`AUTOINCREMENT`, `JSONB`→`TEXT`/`JSON`) при переносе в `dev/`, это не сделано автоматически и не должно считаться тривиальным до фактической попытки.

Также в папке лежат два PDF с нормативными требованиями к чертежам (ГОСТ Р 2.316-2023 и "Технические требования к чертежам") — потенциальный источник правил для Модуля 1.1 (анализ ТТ на чертеже), но их содержимое не распаковано в рамках этой фиксации.
