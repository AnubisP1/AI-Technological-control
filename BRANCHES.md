# Структура веток репозитория

Ветки разделены по назначению: полный проект, размещение на домене и
локальная (offline) разработка по слоям. Ниже — назначение каждой ветки
и правила, которые в ней действуют.

## Обзорная схема

| Ветка | Назначение | Интернет | Домен `aifactorymai.ru` |
|---|---|---|---|
| `main` | Полная копия проекта (эталон) | допускается | допускается |
| `demo_web` | Проект + размещение на домене | допускается | да |
| `web` | Только инфраструктура Cloudflare | — | да |
| `dev_locall` | Ограниченно работающий локальный проект | **запрещён** | **нет** |
| `dev_back` | Бэкенд для локальной сборки | **запрещён** | **нет** |
| `dev_front` | Фронтенд для локальной сборки | **запрещён** | **нет** |
| `api` | Слой API для локальной сборки | **запрещён** | **нет** |

## main

Полная копия проекта целиком: `backend/`, `frontend-v2/`, `frontend/`
(legacy), `deploy/`, документация (`PLAN.md`, `PROGRESS.md`,
`QUESTIONS.md`, `docs/`). Эталонная ветка — остальные ветки порождаются
от неё, изменения в них при необходимости переносятся обратно в `main`.

## demo_web

Весь проект вместе с размещением на домене `aifactorymai.ru`.
Соответствует `main` плюс акцент на продакшен-развёртывании: сборка
фронтенда (`npm run build` → `frontend-v2/dist/`), раздача через Caddy,
публикация наружу через Cloudflare Tunnel.

Запуск всего стека:

```bash
dev/deploy/start-stack.sh   # backend + Caddy + Cloudflare Tunnel
dev/deploy/stop-stack.sh
```

## web

Только то, что относится к размещению на домене через Cloudflare:
конфигурация туннеля, `Caddyfile`, скрипты запуска/остановки стека и
инструкция по развёртыванию. Прикладного кода (backend/frontend) в этой
ветке нет — она описывает инфраструктуру публикации, а не сам продукт.

## dev_locall

Ограниченно работающий локальный проект. Действуют жёсткие правила:

- **никаких обращений по API через интернет** — адаптеры внешних LLM
  (Polza.ai) удалены из кода, а не отключены настройкой; используются
  только локальный Qwen (`llama.cpp`, GGUF из `models/`) и шаблонные
  генераторы;
- **никакой связи с доменом** `aifactorymai.ru` — каталог `deploy/`
  (Caddy, Cloudflare Tunnel) удалён;
- фронтенд обращается к бэкенду только по относительному пути `/api`
  через локальный Vite-прокси на `http://localhost:8000`.

Запуск (два терминала):

```bash
cd dev/backend  && .venv/bin/uvicorn app.main:app --port 8000
cd dev/frontend-v2 && npm run dev          # http://localhost:5174
```

## dev_back / dev_front / api

Ветки-срезы локальной сборки, каждая содержит только свой слой —
для раздельной работы над частями системы:

- `dev_back` — `backend/` (домен, сервисы, инфраструктура, тесты)
  без слоя HTTP-маршрутов;
- `dev_front` — `frontend-v2/` (React + TypeScript, Vite);
- `api` — слой API: `backend/app/api/` и схема приложения
  (`app/main.py`, `app/infrastructure/config.py`).

Так как это срезы, отдельная ветка сама по себе не запускается —
целиком система собирается из `dev_locall` (или `main`). Изменения из
срезов переносятся в `dev_locall`/`main` обычным `git merge`
или `cherry-pick`.
