# Слой API локальной сборки (ветка `api`)

Срез проекта для работы над **HTTP-слоем** локального (offline)
контура: маршруты FastAPI, сборка приложения и контракты домена,
которыми маршруты оперируют. Реализация сервисов и адаптеров вынесена
в ветку `dev_back`, фронтенд — в `dev_front`, целиком система
собирается в `dev_locall` (см. [BRANCHES.md](BRANCHES.md)).

## Что входит

```text
backend/
├── app/
│   ├── api/routes.py       # все HTTP-маршруты
│   ├── main.py             # сборка FastAPI-приложения, CORS, роутер
│   ├── infrastructure/
│   │   └── config.py       # настройки (pydantic-settings, .env)
│   └── domain/             # модели и порты — контракт между API и логикой
└── tests/                  # эндпоинт-тесты (12 шт.)
```

Не входит: `app/services/` и остальная `app/infrastructure/` (ветка
`dev_back`), фронтенд, стек публикации на домене.

## Границы слоя

Маршруты — тонкие: разбор запроса, вызов сервиса, сериализация ответа.
Прикладная логика в них не живёт, поэтому доменные модели и порты здесь
есть, а их реализации — нет. Тяжёлые операции (парсинг STEP, инференс,
voxel-симуляция) запускаются только через `run_heavy` — пул воркеров с
ограничением по CPU, чтобы не блокировать событийный цикл FastAPI.

## Ограничения контура

Ветка наследует правила `dev_locall`: **никаких обращений в интернет** и
никакой связи с доменом `aifactorymai.ru`. В сборке маршрутов это
закреплено явно — `_build_web_search_responder()` всегда возвращает
`None`, а облачные LLM-адаптеры из контура удалены; остаётся только
локальный Qwen, при отсутствии модели — шаблонный текст.

## Тесты

```bash
cd backend
.venv/bin/python -m pytest -q
```

Так как ветка — срез без реализации сервисов, тесты и само приложение
отсюда не запускаются: используйте `dev_locall` или `main`. Изменения
переносятся обратно обычным `git merge` / `cherry-pick`.
