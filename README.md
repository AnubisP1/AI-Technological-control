# Фронтенд локальной сборки (ветка `dev_front`)

Срез проекта для работы над **фронтендом** локального (offline)
контура. Бэкенд вынесен в ветку `dev_back`, слой API — в `api`,
целиком система собирается в `dev_locall` (см. [BRANCHES.md](BRANCHES.md)).

## Что входит

```text
frontend-v2/     # актуальный фронтенд: Vite 7 + React 19 + TypeScript,
                 # Tailwind CSS 4 + shadcn/ui, Framer Motion,
                 # React Three Fiber (3D-просмотр детали и тулпаса),
                 # TanStack Query
frontend/        # legacy-фронтенд Фаз 0–8 (plain JS/CSS), новую работу
                 # здесь не начинать — оставлен для истории до Фазы 16
```

## Запуск

Фронтенд обращается к бэкенду по относительному пути `/api`, который
Vite проксирует на `http://localhost:8000` (см. `vite.config.ts`).
Поэтому для полноценной работы нужен запущенный бэкенд — из ветки
`dev_locall` или `main`:

```bash
cd frontend-v2
npm install
npm run dev          # http://localhost:5174
```

Проверки:

```bash
npm run build        # tsc -b + vite build
npm run lint         # oxlint
```

## Ограничения контура

Ветка наследует правила `dev_locall`: **никаких обращений в интернет**
и никакой связи с доменом `aifactorymai.ru`. Практические следствия для
фронтенда:

- запросы только на относительный `/api` — никаких абсолютных URL и
  переменных окружения с адресом хоста;
- никаких CDN: шрифты, стили и библиотеки ставятся через npm и
  собираются локально;
- данные на экранах — реальный ответ бэкенда либо явная пометка
  «демонстрационные» (как телеметрия цифрового двойника в Модуле 4),
  никогда не выдуманные ради красивой картинки.

## Целевая аудитория и оформление

Интерфейс рассчитан на десктоп; адаптация под мобильные не требуется.
Визуальное направление и токены (палитра, типографика Manrope +
JetBrains Mono) зафиксированы в `UI UX reference/UI UX.md` в корне
репозитория — это утверждённая база, а не предмет свободного поиска.
