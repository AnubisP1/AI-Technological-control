# Бэкенд локальной сборки (ветка `dev_back`)

Срез проекта для работы над **бэкендом** локального (offline) контура:
доменная модель, сервисы и инфраструктура без слоя HTTP-маршрутов.
Слой API вынесен в ветку `api`, фронтенд — в `dev_front`, целиком
система собирается в `dev_locall` (см. [BRANCHES.md](BRANCHES.md)).

## Что входит

```text
backend/
├── app/
│   ├── domain/          # модели предметной области, порты (интерфейсы)
│   ├── services/        # прикладная логика: анализ КД, техпроцесс, тулпас
│   └── infrastructure/  # адаптеры: SQLite НСИ, CAD/STEP, LLM, PDF, CV
└── tests/               # тесты домена, сервисов и инфраструктуры (30 шт.)
```

Не входит: `app/api/routes.py` и `app/main.py` (ветка `api`),
эндпоинт-тесты (там же), фронтенд, стек публикации на домене.

## Ограничения контура

Ветка наследует правила `dev_locall`: **никаких обращений в интернет** и
никакой связи с доменом `aifactorymai.ru`. Облачные LLM-адаптеры удалены;
единственный LLM-путь — локальный Qwen через `llama.cpp`, при отсутствии
модели сервисы отвечают шаблонным текстом. Требование защищено тестами
`backend/tests/test_offline_contour.py` — они падают, если в коде
появится HTTP-клиент, внешний URL или упоминание домена.

## Установка и тесты

```bash
cd backend
python3.11 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m pytest -q
```

Так как ветка — срез без слоя API, приложение целиком отсюда не
запускается: для запуска используйте `dev_locall` или `main`. Изменения
переносятся обратно обычным `git merge` / `cherry-pick`.

## Архитектурные правила

Слои разделены строго: `domain` не знает о `services`, `services` — об
`infrastructure` (зависимость только через порты-интерфейсы из
`domain/*/*_port.py`). ML-модели и внешние библиотеки скрыты за
интерфейсами, чтобы реализацию можно было заменить, не трогая вызывающий
код. Пути — только через `pathlib`, без хардкода разделителей и без
`os.system`. Комментарии и доменная терминология — на русском,
идентификаторы кода — на английском.
